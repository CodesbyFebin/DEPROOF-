# Physical-device qualification

Deproof / DEPR — Built by CodesbyFebin. $DEPR is a brand concept only.

Run `python3 scripts/qualify-device.py` to inspect availability and the APK checksum. With an authorized dedicated physical test device, run `python3 scripts/qualify-device.py --serial SERIAL --install`. This upgrades the APK without clearing app data and sends a launch intent. The script never changes security gates to PASS: successful ADB actions are recorded separately. Without a device every device gate stays NOT_RUN. Older evidence is archived before the next probe.

Use a dedicated devnet wallet and disposable evidence fixtures. Record device model, Android/API version, build fingerprint, APK SHA-256, wallet/version, observed timestamps, steps, expected/actual outcomes and local evidence paths. Never collect wallet seeds, pairing secrets, private keys or authenticated provider URLs. Do not send a mainnet transaction. A screenshot alone does not prove cryptographic checks or hardware security.

| Gate | Procedure and acceptance evidence |
|---|---|
| APK_INSTALL_LAUNCH | Install the checksum-matched APK; open Now, Review, Receipts and nested routes. Observe DEPR and Built by CodesbyFebin, actual UI and no launch crash. Record install result and route screenshots. An ADB launch intent alone is insufficient. |
| WALLET_HANDOFF | With compatible MWA wallet on devnet, connect, decline once, then reconnect. Prepare the memo and explicitly review fee/message. Observe wallet identity, account and cluster. Decline signing and confirm no submission; subsequently approve only the exact memo. Export the receipt and independently observe its known signature. Preserve wallet/version and handoff observations. |
| MESSAGE_MUTATION_REFUSAL | On a disposable debug test build / controlled MWA test wallet, change memo data, blockhash, account/header, signer/writable roles and cluster/evidence context between review and handoff. Invoke the real canSign/validateReturnedTransaction path, not an imitation. Every changed approved message must refuse; new bytes require a new review and fee approval. Existing JVM regression tests are supporting evidence, not this device gate. No production mutation toggle is exposed. |
| RETURNED_SIGNED_BYTES | Use a controlled devnet test wallet to return a valid exact transaction, changed message, invalid signature, wrong signer and malformed/extra signed bytes. Confirm only exact valid bytes proceed, refusal codes are retained and refused results never reach sendTransaction. Record test-wallet source/build and transport observations. If unavailable leave NOT_RUN/BLOCKED; do not substitute direct JVM passes. |
| KEYSTORE_SECURITY_LEVEL | Sign a disposable evidence manifest. Inspect exported localSignature.securityLevel and aliasVersion; independently check Android KeyInfo on that same alias via an instrumented test. Require observed STRONGBOX or TRUSTED_ENVIRONMENT; SOFTWARE/unknown must refuse signing. Run legacy signHash only with 32 raw digest bytes, reject wrong lengths/software keys and independently verify DER/SPKI. Android below API31 remains blocked where precise level cannot be established. Local KeyInfo is not remote attestation. |
| PERMISSION_DENIAL | Cancel the system document picker and camera handoff; deny camera permission in the camera app when applicable. Deproof requests foreground approximate location only after optional consent plus Collect location once. Deny it, revoke it, disable consent during capture, cancel and test offline/disabled providers. Confirm no location field is persisted or exported after denial/removal; valid observations disclose precision/provider/accuracy/mock status. Direct camera permission remains delegated to the system camera app. Observe explicit cancellation/unavailability and no invented photo/evidence receipt. Try revoked/unavailable document access and verify errors. Existing imported private copies must remain intact. |
| LOCAL_WORKFLOWS | Save and reopen a mapping plan, verify ordered coordinates/task linkage and explicit export. Schedule then replace/cancel a reminder; deny notifications and disable all. Test reboot, time change, process death and old-generation broadcasts; no duplicate notification, no post-cancellation notification, no claimed delivery merely from POST_REQUESTED. Change English/Spanish, relaunch, inspect notification text and 200% fonts/screen reader. Keep NOT_RUN until observed. |
| PROCESS_DEATH | Create a task with note/checklist/files; kill only the dedicated test process while idle (`adb shell am force-stop com.aistudio.deproof.sdwk`), relaunch and compare exact persisted bytes. Repeat with pending camera/import, node command and submission intent at controlled boundaries. In-memory unapproved reviews must disappear, uncertain effects must become unknown and must never auto-replay. Force-stop is a separate explicit manual action; the probe never performs it. |
| ROOM_MIGRATION | Install a reproducible v1 fixture build with documented checksum on a disposable device, create event/task/attachment/observation fixtures, then upgrade to current APK without uninstall/clear. Compare exact IDs, bytes, digests and references, verify version2 tables/schema, launch and query successfully. Include failed/rollback migration fixture. SQLite-host tests do not qualify Room-on-device. If v1 fixture APK cannot be produced retain NOT_RUN. |
| CRASH_RECOVERY | Controlled fault injection at file-copy, fsync, FILE_READY and commit boundaries; wallet signed-intent before/after RPC send; node PREPARED/RUNNING before response/commit. Relaunch after process kill; verify FILE_READY bytes before attaching, unknown commands/submissions observed without resend, atomic contributions and stable IDs. Check repeated recovery is idempotent and corrupt files fail closed. Do not inject against production records. |

Store manual observations in a separate timestamped JSON with each gate's PASS, FAIL, BLOCKED or NOT_RUN, concrete evidence references and limitations. Preserve this automatic preflight report. No manual result is consumed as complete qualification until its evidence has been reviewed. An emulator can support UI tests but cannot qualify physical hardware or real wallet acceptance.

Hosting qualification remains limited to the tested fixed Docker profile. Same-owner local educational proof generation/verification does not qualify a production proof system or external-provider integration.

Exercise process death before and after Room commit; inspect any unreferenced staged files without treating them as accepted evidence.
- Restored reminders stay cancelled; no bandwidth consent, node session, operation journal or wallet action is restored/replayed. Android below API 26 must show backup unavailable.

Observe fresh CPU/RAM/backend/circuit values, refusal for stale/unavailable/mismatched profile and expired job, then explicit-consent local execution and independent proof verification. Unsupported hosts and unqualified external providers must display unavailable/BLOCKED, never fabricated capabilities.
